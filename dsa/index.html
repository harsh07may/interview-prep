Concepts

Big-O and hidden costsEstimate the cost before you code, and know which Python operations are secretly linear.

Big-O describes how work grows with input size, ignoring constants. Count the loops, then add the cost of what happens inside them. Space counts the extra memory you allocate, not the input.

The usual trade is memory for speed: a set turns an O(n) search into an O(1) lookup.

# O(n^2) time, O(1) space: compare every pair
def has_duplicate_slow(nums):
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] == nums[j]:
                return True
    return False

# O(n) time, O(n) space: remember what you've seen
def has_duplicate(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return True
        seen.add(x)
    return False

Watch out: Hidden linear costs inside a loop turn O(n) into O(n²): x in some_list, list.pop(0), list.insert(0, x), slicing, and s += c on strings.

Arrays and stringsPython lists are dynamic arrays; strings are immutable, so build them with join.

Indexing and appending are O(1). Inserting or deleting anywhere but the end shifts elements, so it's O(n). Strings can't change in place: convert to a list, edit, and join back.

For lowercase letters, a 26-slot count array is often faster and simpler than a dictionary.

grid = [[0] * 3 for _ in range(2)]   # 2 rows, 3 columns: correct
bad = [[0] * 3] * 2                    # both rows are the SAME list
bad[0][0] = 9                          # bad is now [[9, 0, 0], [9, 0, 0]]

s = "hello"
chars = list(s)
chars[0] = "j"
s = "".join(chars)                     # "jello"
rev = s[::-1]                          # "ollej", O(n) copy

freq = [0] * 26
for ch in "abca":
    freq[ord(ch) - ord("a")] += 1      # freq[0] == 2

Watch out: [[0] * cols] * rows creates one row shared by every index. Always build grids with a comprehension.

Hash maps and setsAverage O(1) insert, delete, and lookup. The tool you'll reach for most often.

dict maps keys to values and set stores unique keys. Counter counts things, and defaultdict removes the "is this key new?" check. Keys must be hashable: numbers, strings, and tuples work; lists and sets don't.

from collections import Counter, defaultdict

counts = Counter("banana")       # Counter({'a': 3, 'n': 2, 'b': 1})
missing = counts["z"]            # 0: missing keys count as zero

groups = defaultdict(list)
for word in ["eat", "tea", "tan"]:
    groups[len(word)].append(word)

ages = {"asha": 31}
ages.get("ravi", 0)              # 0 instead of a KeyError

visited = set()
visited.add((2, 3))              # a tuple can be a key; a list can't
a, b = {1, 2, 3}, {2, 3, 4}
both, either, only_a = a & b, a | b, a - b

Watch out: To use a list as a key, convert it to a tuple first, for example tuple(sorted(word)).

Linked listsNodes pointing to the next node. Most bugs are a missing None check.

No indexing: reaching the k-th node is O(k). In exchange, inserting or removing a node you already hold is O(1). A dummy node placed before the head removes the special case of changing the head itself.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def build(values):
    dummy = ListNode()               # placeholder before the real head
    tail = dummy
    for v in values:
        tail.next = ListNode(v)
        tail = tail.next
    return dummy.next

def to_list(head):
    out = []
    while head:                      # stops cleanly at None
        out.append(head.val)
        head = head.next
    return out

print(to_list(build([1, 2, 3])))     # [1, 2, 3]

Watch out: Check that a node exists before touching node.next. Draw the pointers on paper before rewiring them.

Stacks and queuesLast in, first out and first in, first out. Use a list for a stack and a deque for a queue.

A stack serves the most recent item first: matching brackets, undo, depth-first search. A queue serves the oldest item first: breadth-first search, processing in arrival order. deque gives O(1) operations at both ends.

from collections import deque

stack = []
stack.append(1)
stack.append(2)
top = stack[-1]          # peek: 2
stack.pop()              # 2

queue = deque([1, 2])
queue.append(3)
first = queue.popleft()  # 1, in O(1)

Watch out: list.pop(0) works as a queue but costs O(n) each time, which quietly makes BFS O(n²).

RecursionA function that solves a smaller copy of the same problem, with a base case to stop.

Write the base case first, then trust the recursive call to solve the smaller problem, and combine. Every call waits on the call stack, so recursion uses O(depth) memory.

import sys

def power(base, exp):
    if exp == 0:                          # base case
        return 1
    half = power(base, exp // 2)          # smaller subproblem
    return half * half * (base if exp % 2 else 1)

print(power(2, 10))                       # 1024, in O(log exp) calls
print(sys.getrecursionlimit())            # 1000 by default

Watch out: Python's default recursion limit is 1,000 frames. A skewed tree or a long linked list with 10⁵ nodes raises RecursionError; switch to an explicit stack, or raise the limit with sys.setrecursionlimit as a last resort.

TreesRecursive structures: most tree problems are a DFS that combines answers from the two children.

Depth-first search visits a whole subtree before moving on; the three orders differ only in when you process the node. Breadth-first search visits level by level with a queue. In a binary search tree, an in-order traversal returns the values sorted.

from collections import deque

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def inorder(root, out):
    if not root:
        return
    inorder(root.left, out)
    out.append(root.val)      # preorder: before both calls; postorder: after both
    inorder(root.right, out)

def height(root):
    if not root:
        return 0
    return 1 + max(height(root.left), height(root.right))

def bfs(root):
    order = []
    queue = deque([root] if root else [])
    while queue:
        node = queue.popleft()
        order.append(node.val)
        if node.left:
            queue.append(node.left)
        if node.right:
            queue.append(node.right)
    return order

root = TreeNode(2, TreeNode(1), TreeNode(3))
vals = []
inorder(root, vals)
print(vals, height(root), bfs(root))   # [1, 2, 3] 2 [2, 1, 3]

Watch out: Decide what each call returns before writing it: a height, a boolean, a best-so-far value. Most tree bugs come from mixing "return the answer" with "update a global answer".

Heaps and priority queuesAlways get the smallest item in O(log n). Python's heapq is a min-heap over a plain list.

Use a heap when you repeatedly need the minimum or maximum of a changing collection: top-K, scheduling, merging sorted lists, Dijkstra. heap[0] is the smallest item; the rest of the list is not sorted.

For a max-heap, push negated numbers. Python 3.14 added dedicated functions such as heappush_max, but coding platforms may run older versions, so negation is the portable choice.

import heapq

h = []
for x in [5, 1, 3]:
    heapq.heappush(h, x)
smallest = h[0]                  # 1, peek in O(1)
heapq.heappop(h)                 # 1, O(log n)

nums = [4, 1, 7]
heapq.heapify(nums)              # O(n), in place

max_heap = []
for x in [5, 1, 7]:
    heapq.heappush(max_heap, -x)
largest = -max_heap[0]           # 7

tasks = []
heapq.heappush(tasks, (2, 0, "write"))   # (priority, tie-breaker, item)
heapq.heappush(tasks, (1, 1, "read"))
print(heapq.heappop(tasks)[2])           # read
print(heapq.nlargest(2, [5, 1, 9, 3]))   # [9, 5]

Watch out: Tuples compare item by item. If two priorities tie and the next item can't be compared (a ListNode, say), you get a TypeError; put a counter between them as a tie-breaker.

Graph basicsNodes and edges. Build an adjacency list, then traverse with BFS or DFS and a visited set.

Most problems give you an edge list or a grid. Convert edges into an adjacency list; treat a grid as a graph where each cell connects to its neighbours. Undirected edges go in both directions.

from collections import defaultdict, deque

edges = [[0, 1], [1, 2], [2, 0], [3, 4]]
graph = defaultdict(list)
for a, b in edges:
    graph[a].append(b)
    graph[b].append(a)           # undirected: add both directions

def reachable(start):
    seen = {start}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for nxt in graph[node]:
            if nxt not in seen:
                seen.add(nxt)    # mark when queued, not when popped
                queue.append(nxt)
    return seen

DIRS = [(1, 0), (-1, 0), (0, 1), (0, -1)]
def neighbours(r, c, rows, cols):
    for dr, dc in DIRS:
        nr, nc = r + dr, c + dc
        if 0 <= nr < rows and 0 <= nc < cols:
            yield nr, nc

print(sorted(reachable(0)), list(neighbours(0, 0, 2, 2)))

Watch out: Mark a node visited when you add it to the queue. Marking it when you pop lets the same node be queued many times.

SortingO(n log n) and stable in Python. Often the first step that makes a problem easy.

sorted() returns a new list; list.sort() sorts in place. Sort by several fields with a tuple key, and descending on a number by negating it. Python's sort is stable: equal items keep their original order.

Know merge sort well enough to write it. Its merge step reappears in several problems later.

people = [("asha", 31), ("ravi", 25), ("meera", 31)]
by_age = sorted(people, key=lambda p: p[1])
# [('ravi', 25), ('asha', 31), ('meera', 31)]: asha stays before meera
oldest_first = sorted(people, key=lambda p: (-p[1], p[0]))

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i])
            i += 1
        else:
            out.append(right[j])
            j += 1
    return out + left[i:] + right[j:]

print(merge_sort([5, 2, 4, 1]))   # [1, 2, 4, 5]

Watch out: When an order can't be expressed as a key, functools.cmp_to_key turns a two-argument comparison function into one.

Binary searchHalve the search space each step. Works on any yes/no condition that flips once, not just sorted arrays.

bisect_left finds the first index whose value is at least x; bisect_right finds the first index greater than x. The hand-written template below finds the first value where a condition becomes true. The binary search pattern uses it throughout.

from bisect import bisect_left, bisect_right

a = [1, 3, 3, 3, 7]
bisect_left(a, 3)                          # 1
bisect_right(a, 3)                         # 4
count = bisect_right(a, 3) - bisect_left(a, 3)   # 3

def first_true(lo, hi, ok):
    """Smallest x in [lo, hi) where ok(x) is True, assuming ok goes
    False, ..., False, True, ..., True. Returns hi if none is True."""
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

print(first_true(0, len(a), lambda i: a[i] >= 3))   # 1, same as bisect_left

Watch out: Most binary search bugs are off-by-one errors from mixing templates. Pick one, the half-open [lo, hi) form above, and always write the condition as a function of mid.

The idea behind dynamic programmingSolve each subproblem once and reuse the answer.

DP applies when a problem breaks into smaller versions of itself that overlap, and the best answer is built from the best answers to those pieces. Define three things: the state (what a subproblem is), the transition (how states connect), and the base cases.

Top-down is recursion plus a cache, and is usually easiest to write first. Bottom-up fills a table in order, and often lets you keep only the last few values.

from functools import cache

@cache
def fib(n):                  # top-down: recursion + memo, O(n)
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

def fib_table(n):            # bottom-up, O(1) space
    if n < 2:
        return n
    prev, cur = 0, 1
    for _ in range(n - 1):
        prev, cur = cur, prev + cur
    return cur

print(fib(40), fib_table(40))   # 102334155 102334155

Watch out: @cache needs hashable arguments, so pass indexes rather than lists. Define cached helpers inside the solution method so results don't leak between test cases.

Python habits for problem solvingSmall language details that cause wrong answers or save a lot of code.

Python integers never overflow, which removes a whole class of bugs, but problems that ask for 32-bit behaviour need explicit checks. The itertools and collections modules cover most helpers you'd otherwise hand-write.

from itertools import accumulate, pairwise, combinations

-7 // 2                          # -4: floor division rounds down
int(-7 / 2)                      # -3: truncates toward zero
best = float("inf")              # starting value for a minimum

path, result = [1, 2], []
result.append(path[:])           # save a COPY; path will keep changing

def count_paths(n):
    total = 0
    def dfs(i):
        nonlocal total           # assign to the outer variable
        if i == n:
            total += 1
            return
        dfs(i + 1)
    dfs(0)
    return total

list(accumulate([1, 2, 3]))      # [1, 3, 6], running prefix sums
list(pairwise([1, 2, 3]))        # [(1, 2), (2, 3)], Python 3.10+
list(combinations([1, 2, 3], 2)) # [(1, 2), (1, 3), (2, 3)]

Watch out: Never use a mutable default argument such as def f(seen=set()); the same set is shared across calls. Use None and create it inside.

Pattern 1

Hashing and counting

Trade memory for time: store what you've seen in a hash map or set so each later check is O(1) instead of a scan. It turns many O(n²) brute-force solutions into one O(n) pass.

Recognise it when

  • You ask "have I seen this, or its partner, before?"
  • The problem is about frequencies, duplicates, or grouping
  • Brute force compares every pair, and the input isn't sorted
  • Values fall in a known range, so the array itself can act as the map

Variations

  • Lookup: store items, check for a complement or match
  • Counting: frequency maps with Counter
  • Grouping: map a canonical key to a list of items
  • Index as hash: mark positions in the input array itself for O(1) extra space

Core intuition: Decide what to store (values, counts, or indexes) and what the key is. Check before you insert, so an item never pairs with itself.

Template

from collections import Counter, defaultdict

# 1. Lookup: have I seen what this item needs?
seen = {}                          # key -> index (or count, or item)
for i, x in enumerate(items):
    need = partner_of(x)
    if need in seen:
        pass                       # found: pair (seen[need], i)
    seen[key_of(x)] = i            # insert AFTER checking

# 2. Counting
counts = Counter(items)

# 3. Grouping by a canonical key
groups = defaultdict(list)
for x in items:
    groups[canonical(x)].append(x)

Pseudocode: partner_of, key_of and canonical stand for whatever the problem needs.

Pattern 2

Two pointers

Walk two indexes through the data so that each step rules out part of the search. It usually replaces a nested loop with one pass and O(1) extra space.

Recognise it when

  • The input is sorted, or sorting it won't hurt
  • You're looking for a pair or triplet that meets a target
  • You must modify an array in place with O(1) extra space
  • You compare from both ends, as with palindromes
  • You're merging two sorted sequences

Variations

  • Converging: one pointer at each end, moving inward
  • Read and write: a fast reader and a slow writer compact an array in place
  • Two sequences: one pointer per array, as in a merge
  • Three pointers: partitioning into three regions (Dutch national flag)

Core intuition: Every move must be justified: moving a pointer should throw away only candidates that can't be the answer. If you can't say why a move is safe, the approach is wrong.

Template

# Converging: sorted input, find a pair with a target sum
lo, hi = 0, len(a) - 1
while lo < hi:
    s = a[lo] + a[hi]
    if s == target:
        break                      # found (or record it and move both)
    elif s < target:
        lo += 1                    # need a bigger sum
    else:
        hi -= 1                    # need a smaller sum

# Read and write: keep wanted items, in order, in place
write = 0
for read in range(len(a)):
    if keep(a[read]):
        a[write] = a[read]
        write += 1
# a[:write] now holds the result

Pattern 3

Sliding window

Keep a contiguous window over the input and update its state as the edges move, instead of recomputing every subarray. Most window problems drop from O(n²) or O(n·k) to O(n).

Recognise it when

  • The answer is a contiguous subarray or substring
  • You want the longest, shortest, or count of windows meeting a condition
  • The window's state (sum, counts, distinct items) can be updated as an item enters or leaves
  • The window size is fixed, or validity only breaks as the window grows

Variations

  • Fixed size: add the new item, drop the one that fell out
  • Variable, longest valid: grow, shrink only while invalid
  • Variable, shortest valid: grow until valid, then shrink while still valid
  • Exactly K: count(at most K) minus count(at most K − 1)

Core intuition: The window only works when validity is monotonic: if a window is invalid, every larger window containing it is too (or the reverse). Negative numbers usually break this, which is when you reach for prefix sums instead.

Template

# Variable window: longest window that stays valid
left = 0
best = 0
for right, x in enumerate(a):
    add(x)                          # grow: include a[right]
    while not valid():              # shrink until valid again
        remove(a[left])
        left += 1
    best = max(best, right - left + 1)

# Fixed window of size k
window = sum(a[:k])
best = window
for right in range(k, len(a)):
    window += a[right] - a[right - k]   # add the new item, drop the old one
    best = max(best, window)

Pseudocode: add, remove and valid maintain whatever the window tracks, such as a sum or a Counter.

Pattern 4

Prefix sums and difference arrays

Precompute running totals so any range sum is one subtraction. Combined with a hash map, prefix sums count subarrays with a given sum even when numbers are negative, where a sliding window fails.

Recognise it when

  • You need many range sums, or sums of every subarray
  • The question is about subarrays with sum k, or divisible by k
  • The input can contain negative numbers, so a window's validity isn't monotonic
  • Many updates add a value to a range, and you only read the result at the end

Variations

  • Plain prefix array for O(1) range queries
  • Prefix plus hash map: count or find earlier prefixes
  • Prefix of a transformed array (0 becomes −1, values mod k)
  • Prefix and suffix products or maxima
  • 2-D prefix sums; difference arrays for range updates

Core intuition: The sum of a[i..j] is prefix[j + 1] − prefix[i]. Any question about subarray sums becomes a question about pairs of prefixes, which a hash map answers in one pass.

Template

from itertools import accumulate
from collections import defaultdict

prefix = [0] + list(accumulate(a))       # prefix[i] = sum of a[:i]
range_sum = prefix[j + 1] - prefix[i]    # sum of a[i..j] in O(1)

# Count subarrays summing to k: pairs of prefixes that differ by k
count = running = 0
seen = defaultdict(int)
seen[0] = 1                              # the empty prefix
for x in a:
    running += x
    count += seen[running - k]
    seen[running] += 1

# Difference array: add v to a[l..r] for many updates, rebuild once
diff = [0] * (n + 1)
diff[l] += v
diff[r + 1] -= v
final = list(accumulate(diff[:n]))

Pattern 5

Binary search

Repeatedly halve a search space using a yes/no condition. It applies to sorted arrays, but also to any answer range where "is x good enough?" flips from no to yes exactly once.

Recognise it when

  • The input is sorted, or sorted in pieces (rotated)
  • You need O(log n), or n is huge
  • The question asks for the minimum value that works, or the maximum
  • Checking a candidate answer is easy even though finding it isn't

Variations

  • Exact match and lower or upper bounds
  • Rotated or partly sorted arrays: decide which half is ordered
  • Search on a slope or parity condition, without sorting
  • Binary search on the answer: search the value range with a feasibility check

Core intuition: Write the condition as a function that is False, then True. Binary search finds the boundary. For "maximise the minimum" problems, flip it so the answer is the last True.

Template

def first_true(lo, hi, ok):
    """Smallest x in [lo, hi) with ok(x) True; hi if none."""
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

# On indexes: first position with a[i] >= target
i = first_true(0, len(a), lambda i: a[i] >= target)

# On the answer: smallest value that is feasible
def feasible(x):
    return cost_at(x) <= limit           # must flip False -> True once
answer = first_true(low, high + 1, feasible)

Pattern 6

Linked lists, including fast and slow pointers

Rewire pointers carefully, and use two pointers moving at different speeds to find middles, cycles, and positions from the end without knowing the length.

Recognise it when

  • The input is a linked list
  • You need the middle, or the k-th node from the end, in one pass
  • You must detect a cycle or find where it starts
  • An array's values point to indexes, so it behaves like a linked list

Variations

  • Dummy head to avoid special-casing the first node
  • In-place reversal of all or part of the list
  • Fast and slow pointers: middle, cycle detection, cycle start
  • Gap pointers: move one pointer k steps ahead first
  • Combining steps: find middle, reverse half, merge

Core intuition: Pointer bugs come from losing a reference. Before changing node.next, save whatever you still need. Drawing three boxes on paper is faster than debugging.

Template

# Dummy head: every node, including the first, has a predecessor
dummy = ListNode(0, head)
prev = dummy

# Fast and slow: slow ends at the middle; they meet if there's a cycle
slow = fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow is fast:
        break                        # cycle detected

# Gap pointers: when lead reaches the end, trail is n nodes behind
lead = trail = dummy
for _ in range(n):
    lead = lead.next
while lead.next:
    lead, trail = lead.next, trail.next

Reversal isn't in the template on purpose: Reverse Linked List is the first problem, and doing it by hand is the point.

Pattern 7

Stacks, monotonic stacks, and monotonic deques

A stack holds unfinished work, where the most recent item is resolved first. Keep it monotonic (always increasing or decreasing) and it finds the next or previous greater or smaller element for every item in O(n) total.

Recognise it when

  • Matching or nesting: brackets, tags, nested encodings
  • Evaluating expressions, or undoing the most recent step
  • For each item, find the next or previous greater or smaller item
  • The maximum or minimum of every sliding window
  • A brute force that looks back or forward from each item is O(n²)

Variations

  • Plain stack for matching and evaluation
  • Stack of pairs or states, as in decoding nested strings
  • Monotonic stack for next or previous greater and smaller
  • Monotonic stack used greedily to build the smallest result
  • Monotonic deque for sliding-window extremes

Core intuition: In a monotonic stack, an item is popped the moment its answer arrives, and every item is pushed and popped at most once. That's why the nested-looking while loop is still O(n).

Template

# Monotonic stack: the next greater element for every index
res = [-1] * len(a)
stack = []                           # indexes still waiting for an answer
for i, x in enumerate(a):
    while stack and a[stack[-1]] < x:
        res[stack.pop()] = x         # x is the next greater for that index
    stack.append(i)
# Indexes left on the stack have no greater element to their right

A monotonic deque works the same way but also drops items from the front when they leave the window. Sliding Window Maximum introduces it.

Intervals and sweep line

Sort intervals so overlaps become neighbours, then make one pass. For "how many at once" questions, turn intervals into start and end events and sweep through them in order.

Recognise it when

  • The input is ranges, meetings, bookings, or time slots
  • You're asked to merge, insert, or remove overlapping ranges
  • You need the most overlapping at any moment, or the rooms or groups required
  • Two sorted lists of ranges must be intersected

Variations

  • Sort by start, then merge with the last kept interval
  • Sort by end to keep the most non-overlapping ones (greedy)
  • Sweep line: +1 at a start, −1 at an end
  • Two pointers across two interval lists

Core intuition: Two intervals [a, b] and [c, d] overlap exactly when a ≤ d and c ≤ b. Once sorted by start, you only ever compare an interval with the last one you kept.

Template

# Sweep line: the most intervals overlapping at any moment
events = []
for start, end in intervals:
    events.append((start, 1))
    events.append((end, -1))     # half-open [start, end): at a tie, ends sort first
events.sort()
active = peak = 0
for _, delta in events:
    active += delta
    peak = max(peak, active)

For closed intervals, where touching counts as overlapping, record the end event at end + 1 instead.

Pattern 9

Recursion and backtracking

Build a solution one choice at a time; when a partial solution can't succeed, undo the last choice and try the next. It's a DFS over a tree of decisions, and it's how you generate subsets, permutations, combinations, and constrained arrangements.

Recognise it when

  • "Generate all", "list every", or "count all" arrangements
  • The input is small, often n ≤ 15 to 20, so exponential time is expected
  • Each step is a choice among options, and some partial choices are clearly invalid
  • A problem splits into smaller copies of itself (plain recursion or divide and conquer)

Variations

  • Subsets: include or exclude each item
  • Combinations: choose from a start index onward, with or without reuse
  • Permutations: any unused item in each position
  • Partitioning: choose where the next piece ends
  • Constraint search: grids and boards with pruning

Core intuition: Every backtracking solution is choose, explore, un-choose. Duplicates in the input are handled the same way everywhere: sort, then skip an item equal to the previous one at the same level of the recursion.

Template

def backtrack(start, path):
    if is_complete(path):
        results.append(path[:])      # copy: path keeps changing
        return
    for i in range(start, len(choices)):
        if i > start and choices[i] == choices[i - 1]:
            continue                 # skip duplicate siblings (input sorted)
        if not allowed(i, path):
            continue                 # prune as early as possible
        path.append(choices[i])      # choose
        backtrack(i + 1, path)       # explore (pass i instead to allow reuse)
        path.pop()                   # un-choose

results = []
backtrack(0, [])

Pseudocode: is_complete and allowed are the problem's rules. Drop the duplicate check when the input has no repeats.

Pattern 10

Trees: DFS, BFS, and binary search trees

Most tree problems are a DFS where each node combines answers from its two children, or a BFS that processes one level at a time. In a binary search tree, the ordering lets you skip half the tree at each step.

Recognise it when

  • The input is a tree, or can be turned into one
  • The answer depends on paths, heights, or subtrees
  • Anything "per level": views, averages, widths
  • A BST, where in-order traversal gives sorted values

Variations

  • Bottom-up DFS: children return values, the parent combines them
  • Top-down DFS: pass state such as a running maximum or path downward
  • Global answer updated at each node while returning something else
  • BFS level by level
  • BST: use the ordering to search, validate, or build

Core intuition: Before writing a recursive tree function, decide exactly what it returns for one subtree. When the answer can pass through a node without going to its parent (a diameter, a path sum), return one thing and update a separate global answer.

Template

# Bottom-up DFS: each call reports a value about its subtree
def dfs(node):
    if not node:
        return 0                     # value for an empty subtree
    left, right = dfs(node.left), dfs(node.right)
    # update a global answer here if it can pass through this node
    return 1 + max(left, right)      # what this subtree tells its parent

# BFS, one level at a time
from collections import deque
def by_level(root):
    out, queue = [], deque([root] if root else [])
    while queue:
        level = []
        for _ in range(len(queue)):  # exactly this level's nodes
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        out.append(level)
    return out

Level Order Traversal is the BFS half of this template; solve it once without looking.

Pattern 11

Heaps: top-K, two heaps, and k-way merge

A heap gives the smallest (or largest) item of a changing collection in O(log n). Use it to keep the best k items, to merge several sorted sources, or to split data into two halves for running medians.

Recognise it when

  • "k-th largest", "top k", "k closest", or "k most frequent"
  • You repeatedly need the next smallest or largest as items arrive
  • Several sorted lists or streams must be combined
  • A running median, or a scheduling choice of "best available next"

Variations

  • Size-k heap: keep the k best, discard the rest
  • Greedy with a heap: always take the best available option
  • K-way merge: heap of the current head of each list
  • Two heaps: lower half in a max-heap, upper half in a min-heap

Core intuition: To keep the k largest items, use a min-heap of size k: its top is the weakest of the k, the one to evict. It sounds backwards the first time, and it's the most common heap idea.

Template

import heapq

# Top k largest: a min-heap of size k; its root is the k-th largest
heap = []
for x in items:
    heapq.heappush(heap, x)
    if len(heap) > k:
        heapq.heappop(heap)          # evict the smallest

# K-way merge: always take the smallest current head
heap = [(lst[0], i, 0) for i, lst in enumerate(lists) if lst]
heapq.heapify(heap)
merged = []
while heap:
    val, i, j = heapq.heappop(heap)  # i breaks ties between equal values
    merged.append(val)
    if j + 1 < len(lists[i]):
        heapq.heappush(heap, (lists[i][j + 1], i, j + 1))

Python's heapq is a min-heap. For a max-heap, push negated values (see the Heaps card in Prerequisites).

Pattern 12

Graph traversal: DFS, BFS, and grids

Explore everything reachable from a starting point, marking nodes as visited. DFS is simplest for connectivity and regions; BFS explores in rings, so it finds shortest paths when every edge has the same cost.

Recognise it when

  • A grid of cells, islands, regions, or mazes
  • "Connected", "reachable", "how many groups"
  • Fewest steps or moves when every move costs the same
  • The graph is implicit: states (a lock combination, a word) and the moves between them

Variations

  • Count components: start a new search from each unvisited node
  • Multi-source BFS: start from every source at once
  • Reverse the question: search from the border or the target instead
  • Two-colouring for bipartite checks
  • BFS over (node, extra state), such as keys collected

Core intuition: The only difference between DFS and BFS is the container: a stack or a queue. Mark nodes when you add them, and BFS's first visit to a node is its shortest distance.

Template

from collections import deque

# BFS from one or many sources: shortest distances when every edge costs 1
def bfs(sources, neighbours):
    dist = {s: 0 for s in sources}
    queue = deque(sources)
    while queue:
        node = queue.popleft()
        for nxt in neighbours(node):
            if nxt not in dist:           # first visit is the shortest
                dist[nxt] = dist[node] + 1
                queue.append(nxt)
    return dist

# Grid neighbours as a function, so the same BFS works on grids
def grid_neighbours(grid):
    rows, cols = len(grid), len(grid[0])
    def neighbours(cell):
        r, c = cell
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] != "#":
                yield nr, nc
    return neighbours

For DFS, swap the deque for a list and popleft() for pop(). Iterative DFS avoids Python's recursion limit on large grids.

Pattern 13

Topological sort

Order the nodes of a directed graph so every edge points forward: each task after its prerequisites. It exists exactly when the graph has no cycle, so the same algorithm doubles as cycle detection.

Recognise it when

  • Prerequisites, dependencies, or build order
  • "Can all tasks be finished?", which is cycle detection in a directed graph
  • Longest or earliest-finish time when tasks depend on each other
  • A grid or graph where moves only go "upward", which makes it acyclic

Variations

  • Kahn's algorithm: repeatedly remove nodes with no remaining prerequisites
  • DFS with three colours: unvisited, in progress, done
  • DP along a topological order, such as longest path in a DAG
  • Peeling leaves from an undirected tree

Core intuition: A node with in-degree zero has nothing blocking it, so it can go next. Removing it may free up others. If you get stuck before placing every node, the rest form a cycle.

Template

from collections import deque, defaultdict

def topo_order(n, edges):              # edge (a, b): a must come before b
    graph = defaultdict(list)
    indegree = [0] * n
    for a, b in edges:
        graph[a].append(b)
        indegree[b] += 1
    queue = deque(i for i in range(n) if indegree[i] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph[node]:
            indegree[nxt] -= 1
            if indegree[nxt] == 0:
                queue.append(nxt)
    return order if len(order) == n else []   # shorter means a cycle

Pattern 14

Union-find

A disjoint-set structure that tracks which items belong to the same group. Joining two groups and asking "same group?" are both nearly O(1), which makes it ideal when connections arrive one at a time.

Recognise it when

  • Connected components, especially as edges are added
  • "Would this edge create a cycle?" in an undirected graph
  • Grouping items that are linked by equality or shared attributes
  • Kruskal's minimum spanning tree

Variations

  • Count components: each successful union removes one
  • Detect the edge that closes a cycle
  • Union first, then check constraints
  • Union indexes, then work within each group
  • Weighted union-find that stores ratios to the root

Core intuition: Each group has a representative, its root. find follows parents to the root; union points one root at the other. Path compression and union by size keep the trees almost flat.

Template

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]   # path halving
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                   # already in the same group
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra               # attach the smaller tree
        self.size[ra] += self.size[rb]
        return True

The iterative find avoids Python's recursion limit. Returning False from union is how you detect a cycle.

Pattern 15

Shortest paths and minimum spanning trees

When edges have different costs, BFS no longer gives shortest paths. Dijkstra's algorithm does, for non-negative weights; Bellman-Ford handles limits on the number of edges; minimum spanning trees connect everything as cheaply as possible.

Recognise it when

  • Weighted edges and a "cheapest", "fastest", or "minimum cost" path
  • A path's cost is its worst step rather than its total
  • A limit on the number of edges, stops, or hops
  • "Connect all points at minimum total cost"

Variations

  • Dijkstra: shortest paths from one source, non-negative weights
  • Minimax Dijkstra: the cost is the maximum edge on the path
  • Bellman-Ford: shortest paths using at most k edges
  • 0-1 BFS: weights of only 0 and 1, with a deque
  • Floyd–Warshall: all pairs on small graphs
  • Prim and Kruskal: minimum spanning trees

Core intuition: Dijkstra always expands the closest unfinished node; with non-negative weights, nothing found later can make it closer. A heap entry older than the node's best known distance is stale and gets skipped.

Template

import heapq
from collections import defaultdict

def dijkstra(n, edges, src):              # edges: (u, v, w) with w >= 0
    graph = defaultdict(list)
    for u, v, w in edges:
        graph[u].append((v, w))
    dist = [float("inf")] * n
    dist[src] = 0
    heap = [(0, src)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:
            continue                       # stale entry
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(heap, (dist[v], v))
    return dist

Pattern 17

Dynamic programming: one dimension

Define an answer for each position (or amount), express it through answers you've already got, and solve each one once. The state is a single index.

Recognise it when

  • Count ways, or find the minimum or maximum, over a sequence
  • Each step is a small choice, such as take or skip, and choices affect what's allowed next
  • Recursion would repeat the same subproblems
  • The answer at i depends only on a few earlier (or later) positions

Variations

  • Take or skip: House Robber shape
  • Ways to reach: sum over the last step
  • Prefix feasibility: can the first i items be split validly?
  • Track two values, such as a max and a min
  • Solve from the back when choices jump forward

Core intuition: Write the state in words first, for example "f(i) = the most money from houses i onward". Then the recurrence is just the choices at i. Top-down with @cache is easiest to get right; convert to a loop with a few variables once it works.

Template

from functools import cache

def top_down(a):
    @cache
    def f(i):                           # best answer using a[i:]
        if i >= len(a):
            return 0                    # base case
        take = a[i] + f(i + 2)          # the choices at i ...
        skip = f(i + 1)
        return max(take, skip)          # ... combined
    return f(0)

def bottom_up(a):
    nxt1 = nxt2 = 0                     # f(i + 1) and f(i + 2)
    for i in range(len(a) - 1, -1, -1):
        nxt1, nxt2 = max(a[i] + nxt2, nxt1), nxt1
    return nxt1

Pattern 18

Dynamic programming: knapsack and subset sums

Choose items to hit or stay within a capacity: a sum, an amount, or a budget. The state is "capacity used", and the loop order decides whether items can repeat and whether order matters.

Recognise it when

  • Pick a subset that sums to a target, or split items into two groups
  • Make an amount from coins or numbers
  • Each item has a cost and you have a budget
  • Signs, partitions, or "closest to half" in disguise

Variations

  • 0/1: each item at most once, capacity loop runs downward
  • Unbounded: items reusable, capacity loop runs upward
  • Counting combinations: items in the outer loop
  • Counting ordered sequences: capacity in the outer loop
  • Two capacities at once

Core intuition: In a one-row table, the direction of the capacity loop is the whole difference between "once" and "reusable". Going downward reads values from before this item was considered; going upward lets the item be used again.

Template

# 0/1 knapsack (each item once): capacity loop goes DOWN
best = [0] * (cap + 1)                 # best[c] = best value within capacity c
for weight, value in items:
    for c in range(cap, weight - 1, -1):
        best[c] = max(best[c], best[c - weight] + value)

# Unbounded (items reusable): capacity loop goes UP
best = [0] * (cap + 1)
for weight, value in items:
    for c in range(weight, cap + 1):
        best[c] = max(best[c], best[c - weight] + value)

For counting, combinations put items in the outer loop; ordered sequences put the capacity in the outer loop. Coin Change II and Combination Sum IV show the difference.

Pattern 19

Dynamic programming: grids and two strings

The state is two indexes: a cell in a grid, or a position in each of two strings. Fill a table where each cell depends on its neighbours above, to the left, and diagonally.

Recognise it when

  • Paths through a grid that move only right and down
  • Comparing, aligning, or transforming two strings
  • Palindromes within one string (the two indexes are its ends)
  • "How many ways can s produce t" or "does s match pattern p"

Variations

  • Grid paths: count or minimise
  • Two strings: match extends the diagonal, mismatch chooses a neighbour
  • Palindromes: expand around centres, or fill by length
  • Squares and shapes: combine three neighbours
  • Pattern matching with wildcards

Core intuition: Use an extra row and column for empty prefixes, so dp[i][j] is about a[:i] and b[:j]. Every cell then reads only the row above, which is also why one row of memory is enough.

Template

# dp[i][j] answers the question for prefixes a[:i] and b[:j]
m, n = len(a), len(b)
dp = [[0] * (n + 1) for _ in range(m + 1)]   # row 0 / column 0: empty prefix
for i in range(1, m + 1):
    for j in range(1, n + 1):
        if a[i - 1] == b[j - 1]:
            dp[i][j] = dp[i - 1][j - 1] + 1
        else:
            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
answer = dp[m][n]

This example is Longest Common Subsequence; most problems below change only the two lines inside the loop.

Pattern 20

Dynamic programming: advanced shapes

The same idea, with less obvious states: the best subsequence ending at each item, a small set of states per day, answers over every range, a set of used items as a bitmask, or a value returned from each tree node.

Recognise it when

  • Longest increasing or chained subsequence
  • Buy and sell rules, cooldowns, or transaction limits
  • The cost of a range depends on how you split it, or two players take turns
  • n is at most about 20 and the state is "which items are used"
  • Choices on a tree, where each node's answer depends on its children

Variations

  • Longest increasing subsequence, O(n²) and O(n log n)
  • State machines: a few states updated each step
  • Interval DP: fill by range length
  • Bitmask DP over subsets
  • DP on trees: return a tuple of states from each node

Core intuition: When a DP feels impossible, the state is usually missing information. Ask what you'd need to know to continue from here (holding stock or not, which items are used, which balloon goes last) and add exactly that.

Template

from bisect import bisect_left

# Longest strictly increasing subsequence in O(n log n)
tails = []          # tails[k] = smallest tail of an increasing run of length k + 1
for x in nums:
    k = bisect_left(tails, x)
    if k == len(tails):
        tails.append(x)
    else:
        tails[k] = x
lis_length = len(tails)

# Interval DP: shortest ranges first, so every sub-range is ready
for length in range(2, n + 1):
    for i in range(n - length + 1):
        j = i + length - 1
        dp[i][j] = max(dp[i][k] + dp[k + 1][j] + cost(i, k, j) for k in range(i, j))

tails is not itself a valid subsequence; only its length is meaningful. The interval part is pseudocode for the shape.

Pattern 21

Tries

A tree of characters where each path from the root spells a prefix. It answers "does any word start with this?" in time proportional to the prefix, however many words are stored.

Recognise it when

  • Many words, and questions about prefixes
  • Autocomplete, spell-check, or replacing words by their roots
  • Searching a grid or pattern for many words at once
  • Maximising XOR, where numbers are treated as strings of bits

Variations

  • Plain trie: insert, search, and prefix search
  • Wildcard search that branches at a dot
  • Extra data stored at each node, such as top suggestions
  • Trie plus backtracking on a grid
  • Binary trie over the bits of numbers

Core intuition: Words that share a prefix share a path, so one walk down the trie tests every word with that prefix at once. That's why tries shine when you'd otherwise check many words at every step.

Template

class TrieNode:
    __slots__ = ("children", "end")
    def __init__(self):
        self.children = {}
        self.end = False               # a word ends at this node

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.end = True

    def find(self, prefix):            # the node for this prefix, or None
        node = self.root
        for ch in prefix:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

Implement Trie is this class plus two one-line methods; write it once yourself before using the template.

Pattern 22

Bit manipulation

Treat integers as rows of bits. A handful of identities, such as XOR cancelling pairs and x & (x − 1) clearing the lowest bit, solve problems that look like they need extra memory.

Recognise it when

  • "Every element appears twice except one"
  • O(1) extra space with values in a known range
  • Counting set bits, powers of two, or reversing bits
  • Addition or arithmetic without the usual operators
  • Sets of up to about 20 items represented as a mask

Variations

  • XOR to cancel pairs
  • Clearing or isolating the lowest set bit
  • Counting each bit position across all numbers
  • Masks for 32-bit behaviour in Python

Core intuition: XOR is addition without carrying: it's its own inverse, so anything XORed twice disappears. Python integers are unbounded, so problems about 32-bit numbers need an explicit mask.

Template

x & 1              # lowest bit: is x odd?
x >> 1             # halve, rounding down
x & (x - 1)        # clear the lowest set bit
x & -x             # keep only the lowest set bit
x ^ x == 0         # XOR cancels pairs, and x ^ 0 == x
(mask >> i) & 1    # is bit i set?
mask | (1 << i)    # set bit i
x.bit_count()      # number of set bits (Python 3.10+)
MASK = 0xFFFFFFFF  # emulate 32 bits; convert back if the top bit is set

Pattern 25 (optional)

Range queries and string algorithms

Tools that rarely appear in standard interviews but make certain problems tractable: trees that answer range sums under updates, merge sort that counts while it sorts, and linear-time string matching.

Recognise it when

  • Range sums or counts while values keep changing
  • "How many elements to the right are smaller?"
  • Substring search, repeated prefixes, or borders of a string
  • Duplicate substrings, where hashing windows helps

Variations

  • Fenwick tree: point update, prefix sum
  • Coordinate compression to index by rank
  • Merge sort that counts pairs while merging
  • Prefix function (KMP) for prefix-suffix matching
  • Rolling hash with binary search on length

Core intuition: Treat this section as long-term strength rather than must-know interview material. If time is short, skip it; the rest of the sheet covers what interviews usually ask.

Template

class Fenwick:                         # prefix sums with updates, both O(log n)
    def __init__(self, n):
        self.tree = [0] * (n + 1)      # 1-indexed
    def add(self, i, delta):           # a[i] += delta, i is 1-based
        while i < len(self.tree):
            self.tree[i] += delta
            i += i & -i
    def prefix(self, i):               # sum of a[1..i]
        total = 0
        while i > 0:
            total += self.tree[i]
            i -= i & -i
        return total

def prefix_function(s):
    """pi[i] = length of the longest proper prefix of s[:i + 1] that is also its suffix."""
    pi = [0] * len(s)
    k = 0
    for i in range(1, len(s)):
        while k and s[i] != s[k]:
            k = pi[k - 1]
        if s[i] == s[k]:
            k += 1
        pi[i] = k
    return pi

i & -i, from the bit manipulation pattern, is what makes the Fenwick tree work.

    Hint

    Which letters must come in pairs, and how many can sit in the middle?

    Reveal the pattern

    Same idea as: Valid Anagram

    Hint

    Can you do it in place with O(1) extra space, using an operation you already know well?

    Reveal the pattern

    Same idea as: The converging pointers in Valid Palindrome

    Hint

    Removing elements from both ends leaves what in the middle?

    Reveal the pattern

    Same idea as: Maximum Points You Can Obtain from Cards

    Hint

    Replace each number with whether it's odd. What's the question now?

    Same idea as: The counting walk in Kth Smallest Element in a Sorted Matrix

  7. Minimum Number of Days to Make m BouquetsMediumLeetCode 1482

    Hint

    Same idea as: Koko Eating Bananas

  8. Minimum Number of Arrows to Burst BalloonsMediumLeetCode 452

    Hint

    Where should the first arrow go to burst as many balloons as possible?

    Same idea as: Non-overlapping Intervals

  9. Remove Duplicate LettersMediumLeetCode 316

    Hint

    When is it safe to remove a letter you've already placed?

    Reveal the pattern

    Same idea as: Remove K Digits

  10. Sum of Subarray MinimumsMediumLeetCode 907

    Hint

    Instead of looping over subarrays, ask how many subarrays each element is the minimum of.

    Reveal the pattern

    Monotonic stack (contribution counting). Find each element's previous-smaller and next-smaller boundaries; it's the minimum of left × right subarrays. Use < on one side and ≤ on the other so equal values aren't double-counted.

    Same idea as: Largest Rectangle in Histogram

  11. Sum Root to Leaf NumbersMediumLeetCode 129

    Hint

    Same idea as: Count Good Nodes in Binary Tree

  12. Letter Tile PossibilitiesMediumLeetCode 1079

    Hint

    Tiles repeat, and every non-empty sequence counts, not only full-length ones.

    Reveal the pattern

    Backtracking over counts. Recurse over letter counts: for each letter with a count left, use one, add 1 to the total, recurse, and restore. Working on counts avoids duplicate sequences without any sorting tricks.

    Same idea as: Permutations II

  13. Number of Closed IslandsMediumLeetCode 1254

    Hint

    Which land cells can never belong to the answer?

    Reveal the pattern

    Grid DFS (eliminate the border first). Flood-fill all land connected to the border first; every island found after that is closed. Here 0 is land and 1 is water.

    Same idea as: Surrounded Regions

  14. Most Stones Removed with Same Row or ColumnMediumLeetCode 947

    Hint

    When can you remove a stone, and what remains when you can't remove any more?

    Reveal the pattern

    Union-find (connected components). Stones sharing a row or column are connected, and each component shrinks to one stone. Answer: stones minus components. Union each stone's row with its (offset) column to avoid comparing all pairs.

    Same idea as: Number of Provinces

  15. Path with Maximum ProbabilityMediumLeetCode 1514

    Hint

    Probabilities multiply along a path and can only shrink.

    Reveal the pattern

    Dijkstra (maximising a product). Use a max-heap on probability and relax with multiplication. It works because multiplying by values between 0 and 1 never increases a path's probability.

    Same idea as: Path With Minimum Effort

  16. Furthest Building You Can ReachMediumLeetCode 1642

    Hint

    Which climbs deserve the ladders?

    Reveal the pattern

    Greedy with a heap. Put every climb in a min-heap as if using a ladder. When the heap holds more climbs than you have ladders, pay for the smallest with bricks; stop when bricks run out.

    Same idea as: Minimum Number of Refueling Stops

  17. Partition Array for Maximum SumMediumLeetCode 1043

    Hint

    Think about where the last group ends.

    Reveal the pattern

    1-D dynamic programming. dp[i] is the best for the first i elements: the maximum over group lengths L ≤ k of dp[i − L] + L × max(last L elements), updating the max as L grows.

    Same idea as: Word Break's "last piece" recurrence

  18. Longest Palindromic SubsequenceMediumLeetCode 516

    Hint

    A palindrome reads the same reversed.

    Reveal the pattern

    Two-string DP (or interval DP). It's the Longest Common Subsequence of s and its reverse. Or fill by range: matching ends add 2, otherwise drop one end.

    Same idea as: Longest Common Subsequence

  19. Sliding PuzzleHardLeetCode 773

    Hint

    The board is tiny. How many different boards can there be?

    Reveal the pattern

    BFS on an implicit graph of states. Encode each board as a string; neighbours swap 0 with an adjacent cell (precompute the neighbours of each of the six positions). There are at most 720 states.

    Same idea as: Open the Lock

  20. Trapping Rain Water IIHardLeetCode 407

    Hint

    Water is held in by the lowest wall around it, and the border is the first wall.

    Reveal the pattern
